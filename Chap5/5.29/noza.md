# 問題 5.29

`Chap5` で `racket 5.29/noza.rkt` を実行し、次の定義と `(fib n)` を入力する。5.26 の末尾再帰を保つ監視つき評価器を再利用する。

```scheme
(define (fib n)
  (if (< n 2)
      n
      (+ (fib (- n 1)) (fib (- n 2)))))
```

定義時の統計を除いた実測値は次のとおり。

| n | Fib(n) | プッシュ回数 | 最大深さ |
|---:|---:|---:|---:|
| 0 | 0 | 16 | 8 |
| 1 | 1 | 16 | 8 |
| 2 | 1 | 72 | 13 |
| 3 | 2 | 128 | 18 |
| 4 | 3 | 240 | 23 |
| 5 | 5 | 408 | 28 |
| 6 | 8 | 688 | 33 |
| 7 | 13 | 1136 | 38 |
| 8 | 21 | 1864 | 43 |
| 9 | 34 | 3040 | 48 |
| 10 | 55 | 4944 | 53 |

## a. 最大深さ

`n ≥ 2` では `D(n) = 5n + 3`。

`D(1) = 8` で、第1引数の `(fib (- n 1))` を評価するとき、外側の加算を再開するための5個が残る。第2引数側では3個が残るため、こちらが最大深さを超えることはない。

したがって `D(2) = 13`、以後 `D(n) = D(n − 1) + 5` となり、`D(n) = 13 + 5(n − 2) = 5n + 3`。両方の枝は順番に評価されるので、木全体の呼び出し数ではなく、最も深い経路の長さに比例する。

## b. プッシュの総数

基底の場合は `S(0) = S(1) = 16`。`n ≥ 2` では、

```text
S(n) = S(n − 1) + S(n − 2) + 40
```

となり、オーバーヘッドは `k = 40`。

`S(n − 1)` と `S(n − 2)` にはそれぞれ単独の `(fib ...)` 呼び出しの5回が含まれる。残る40回は、現在の呼び出しの5回、条件判定の11回、加算の8回、2回の減算の各8回を合わせたものになる。

`S(n) = a Fib(n + 1) + b` を代入すると、Fibonacci の漸化式から `b = 2b + 40`、つまり `b = −40`。さらに `S(0) = 16` より `a − 40 = 16` なので `a = 56`。`S(1) = 16` も満たすため、帰納的に

```text
S(n) = 56 Fib(n + 1) − 40
```

が成り立つ。プッシュ回数は Fibonacci 数と同じく指数的に増加する。
